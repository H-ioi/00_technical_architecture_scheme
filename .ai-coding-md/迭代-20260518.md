# 迭代-20260518

## uni-search-form 样式在 admin-web 中不生效（排查结论）

**说明**：`scoped` 本身没有问题。业务侧正常引入同一版本的 `uni-ui-lib`（`dist/index.mjs` + `uni-ui-lib/style.css` / `index.css`）时，`data-v-*` 与样式选择器一致，可以正常加载。

**异常场景**：若联调时出现「组件 JS 与全局 CSS 不是同一次构建」（例如 link、`file:`、未 rebuild、或 Vite 依赖缓存混用），会出现 DOM 上的 `data-v-*` 与 `index.css` 里不一致，表现为组件样式「像没加载」。

**联调习惯**：改 `uni-lib` 后执行 `yarn uni-lib:build`（或 `uni-lib` 内 `npm run build`），必要时 `vite --force`。

## uni-lib 组件样式去掉 scoped

**范围**：`uni-lib/src` 下全部 Vue 组件的 `<style scoped>` 改为非 scoped；原 `:deep(...)` 改为在对应根类（如 `.uni-data-table`、`.uni-theme-settings`、`.uni-layout-tags`）下嵌套的普通选择器。

**目的**：打包后的 `dist/index.css` 不再依赖 `data-v-*`，业务侧 JS/CSS 不同步时布局类样式仍可命中。

**说明**：`uni-layout/index.vue` 中原先用于 Teleport 下拉的第二个 `<style lang="scss">`（`.uni-layout-user-dropdown`）保持不变。

**内容**：活动详情切换子 Tab 时通过刷新 key 重新挂载当前子组件，恢复旧版切 Tab 即拉取当前 Tab 数据的行为；问卷内容 Tab 增加旧版存在的导出入口，调用当前问卷答卷导出能力。

**补齐**：报名人数列表增加活动名称与报名 ID 列；签到人数列表增加创建时间列，并同步到结束态 CSV 导出。

**规则**：祝福语批量可见/不可见增加二次确认，空可见状态显示为空值而不是误判为“否”；活动反馈导出按钮按旧版在进行中与已结束均可显示，批量可见提交体收敛为 `{ id, visible }`，不再提交整行展示字段。

## 活动详情表格列与请求体继续对齐

**范围**：`admin-web/src/views/activity/detail`。

**内容**：详情 Tab 顺序按旧版恢复为基本信息、活动项目、问卷内容、报名人数、签到人数、获奖名单、投票信息、祝福语内容、活动反馈；报名人数列顺序补齐旧版序号、活动名称、电话、邮箱、姓名、票价、实付、人数、报名 ID；签到人数移除旧版表格未展示的「允许抽奖」列。

**规则**：祝福语报名字段文案改为旧版「报名ID」；反馈批量可见/不可见补二次确认；新增投票记录未选择签到记录时按旧版传 `codeId: 0`，避免提交 `NaN`。

## 活动详情抽奖奖品展示对齐

**范围**：`admin-web/src/views/activity/detail/tabs/program-cards.vue` 与活动文案。

**内容**：活动项目 Card 在抽奖类项目下补回旧版奖品列表展示，按项目调用奖品 `listByProgram` 接口，展示奖品名称、金额和图片预览。

**说明**：旧版奖品接口调用代码处于注释状态，但模板保留了奖品列表展示能力；新版已有按项目查奖品接口，因此补齐为可展示能力。获奖名单导出文件名解析依赖响应头，当前 `uni-lib` 请求封装只向业务层返回响应数据，暂不扩大范围改请求层。
