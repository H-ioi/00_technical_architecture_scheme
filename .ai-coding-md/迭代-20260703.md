# 迭代-20260703 — 规则体系职责边界分离

## 背景

四份规则（Guide / PC Platform / Mobile Platform / Checker）存在职责重叠：Platform 内含 Critical 清单、评审输出、行数/内联/lint 等与 Checker、Guide 重复，导致 AI 裁决来源不清。

## 改动摘要

### 1. AI-PC架构校验Skill（uni-review-web）

- **删除：** §8 内联原则、§9 命名、§11 注释、§14 lint/test、§15 Critical 禁止清单、§16 评审输出、§17 Finish Checklist
- **改写：** 「禁止」→「项目约定」/「不采用」/「推荐」
- **保留：** admin-web 目录、uni-ui-lib、list.config、权限、router、api/modules、stores、页面形态等独有架构
- **引用：** 编码原则 → Guide；违规判定 → Checker

### 2. AI-Mobile架构校验Skill（uni-review-mobile）

- **删除：** §7 内联、§8 命名、§9 注释、§10 lint、§11 Critical、§12 评审输出、§13 Finish Checklist
- **改写：** 同上，「禁止」→「项目约定」
- **保留：** pages.json、manifest、utils/request、api 形态、跨端、static、locales 等

### 3. AI-全局编码规则（Guide）

- **统一阈值：** 33 行（函数）、**450 行**（建议评估）、800 行（必须拆分）
- 明确 Guide / Checker **共用**同一套行数阈值

### 4. AI-代码校验Skill（Checker）

- **去项目化：** 不再写「后台必须…」「移动必须…」
- **平台专项：** 新增 CHK-PLATFORM-01 — 存在 Platform Skill 时动态引用其项目约定
- **CHK-FILE-01：** Warning 阈值 500 → **450**，引用 Guide
- **保留：** CHK-xxx、Critical/Warning/Pass、质量门禁、评审输出、Finish Checklist

## 四层职责（目标态）

```
Guide     → 怎么写（思维、拆分、数据流、TS、Vue…）
Platform  → 项目长什么样（目录、分层、组件库、约定）
Checker   → 怎么判（CHK-xxx、等级、输出、门禁）
```
