- `UniLayout` 标签栏显示跟随 `appStore.showTags`，框架布局优先使用用户保存的 `data-layout`。
- `UniLayout` 拆出 `sidebar.vue`、`header.vue`，`index.vue` 仅保留状态编排、插槽转发和路由/store 接线；布局样式迁入 `components.scss`。
- `uni-layout/components` 内部组件统一短命名：`menu.vue`、`password.vue`、`tags.vue`，去除 `layout-*` / `*-view` 等冗余文件名。
- `uni-layout` 对外只导出/注册 `UniLayout`，下级组件不再从组件库入口或安装器暴露。

### 注意事项

- 后续新增主题时直接在 `variables.scss` 增加 `[data-layout='xxx']` 规则，并在主题设置面板补充对应选项。

## FIX-001：登录后权限码未写入 localStorage

### 修改文件

- `admin-web/src/api/modules/auth.ts`（OAuth 响应归一化 + `fetch` 绕过业务壳解包）
- `admin-web/src/router/index.ts`（菜单权限与登录权限合并，避免覆盖丢失）
- `admin-web/src/types/auth.ts`（`authorities` 项支持 `permission` 字段）

### 核心逻辑变更点

- 根因：`uni-ui-lib` 默认 `unwrapApiEnvelope` 解包 `{ code, data }` 时只保留 `data`，`user_info.authorities` 若在外层则被丢弃；`flatAuth` 得到空数组，`permission-codes` 缓存为空。
- 登录改用 `fetch` 读取原始 OAuth JSON，经 `normalizeOAuthToken` 合并 `data` 与外层 `user_info`/`userInfo`（含 JSON 字符串形态）。
- 路由守卫拉菜单后合并权限码，不再用菜单子集覆盖登录时下发的全量 authorities。

### 注意事项

- 权限缓存键为 `uni-admin-web:permission-codes`（非旧版 `permissions`）。
- 验证：登录后 DevTools → Application → Local Storage 检查该键应含 `announcement_add` 等码；按钮 `v-uni-permission` 应可见。
