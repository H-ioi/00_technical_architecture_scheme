# I18n

`createUniI18nBridge()`（定义见 `locales/i18n.ts`）用于桥接宿主工程的 `vue-i18n`。组件库通过 **`useUniI18n().t` 调用宿主的 `i18n.global.t`**，不在库内再做文案表解析。

默认中英文文案以 **`uniLibMessagesNested`** 导出；请在创建 `vue-i18n` 实例时将其 **深度合并** 进各语言的 `messages`（业务文案后合并，便于覆盖库内 key）。

## 与 Element Plus 语言包同步

业务里自己写的文案可通过 `t()` 与 `vue-i18n` 一致；**组件库内部使用的 Element Plus 原子组件**（如 `ElDatePicker`、`ElPagination`）依赖 Element Plus 自带的语言包，需与当前界面语言一致。

推荐做法：

1. 在根节点用 **UniConfigProvider** 包裹应用（内部使用 Element Plus 的 `ElConfigProvider` 注入 `locale`）。
2. 建立 i18n 桥接时传入 **`localeRef`**（与 `vue-i18n` 的 `locale` 引用一致），这样切换语言时不仅业务文案会变，**日期选择器、分页等**也会一起更新。

```ts
import { useI18n } from "vue-i18n";
import { createUniI18nBridge } from "uni-ui-lib";

const i18n = useI18n();

createUniI18nBridge({
  t: i18n.t,
  locale: () => i18n.locale.value,
  setLocale: (next) => {
    i18n.locale.value = next;
  },
  localeRef: i18n.locale,
});
```

## 覆盖组件库文案

在 `vue-i18n` 的 `messages` 中为对应 key 提供翻译即可（例如 `common.empty`、`layout.submit`、`dataTable.refresh`）。key 与嵌套结构见包内 `uniLibMessagesNested`。

未传 `localeRef` 时，`UniConfigProvider` 仍会根据 `locale()` 的**当前值**解析一次 Element Plus 语言包（适合静态语言场景）；**动态切换语言**时请务必传 `localeRef`。

语言代码到 Element Plus 包的映射由 `resolveElementPlusLocale()` 完成（目前内置 `zh-*` → 中文、`en*` → 英文，其余默认中文）。需要更多语言时可在业务侧自行用 `el-config-provider` 覆盖，或向组件库贡献映射。
